# Thesis Proposal

## Попередня робоча назва

- **Українською:** Децентралізована система верифікації документів на основі власної реалізації блокчейн-технології
- **Англійською:** Decentralized Document Verification System Based on a Custom Blockchain Implementation

## Актуальність та проблематика

Верифікація автентичності офіційних документів (дипломів, сертифікатів, атестатів) традиційно вимагає прямого звернення до установи-видавця, що є повільним, залежним від доступності реєстратора та вразливим до людського фактора. Централізовані реєстри становлять єдину точку відмови та потенційну ціль для підробки або несанкціонованої модифікації записів заднім числом.

Складність проблеми полягає не лише в забезпеченні незмінності реєстру, а й у виборі механізму досягнення консенсусу між розподіленими вузлами мережі: різні алгоритми консенсусу по-різному балансують швидкість підтвердження запису, обчислювальні витрати та стійкість до атак (зокрема Sybil-атаки — створення зловмисником множини фіктивних вузлів для отримання непропорційного впливу на консенсус). Порівняльний аналіз цих компромісів у контексті саме верифікації документів становить наукову новизну роботи.

## Сформована ідея продукту

Тип системи з архітектурної точки зору — **розподілена P2P-мережа вузлів (blockchain-вузлів) із власною реалізацією структури блокчейну та алгоритмів консенсусу**, без використання готових блокчейн-платформ (Ethereum, Hyperledger тощо). Кожен вузол мережі підтримує повну копію ланцюга блоків, обмінюється блоками з іншими вузлами через P2P-протокол та бере участь у досягненні консенсусу щодо наступного блока. Поверх мережі вузлів розгортається веб-застосунок (SPA), що надає інтерфейс для видачі документів установою та їх верифікації будь-яким користувачем за хешем.

## Core Features

1. **Видача документа установою** — заклад формує документ, система обчислює його цифровий відбиток, підписує від імені установи та фіксує запис у спільному реєстрі; власник отримує посилання/QR-код для подальшого підтвердження.
2. **Миттєва верифікація документа** — будь-хто (роботодавець, інша установа) перевіряє автентичність документа за хешем або QR-кодом без звернення до видавця й отримує однозначний статус: справжній / підроблений / відкликаний.
3. **Виявлення підробки та заднього датування** — будь-яка розбіжність між пред'явленим документом і записом у реєстрі, а також спроба підмінити дату видачі заднім числом, автоматично позначається як невалідна.
4. **Незмінний журнал видачі** — установа бачить повну історію власної видачі документів; цілісність усього ланцюга записів перевіряється автоматично.
5. **Відкликання документа** — установа-видавець може відкликати раніше виданий документ (помилка, шахрайство); статус відкликання одразу враховується під час верифікації.
6. **Багатоустановна мережа без єдиної точки контролю** — кілька незалежних установ ведуть спільний реєстр; жодна установа одноосібно не може підмінити чи видалити чужий запис.
7. **Дослідницьке порівняння алгоритмів консенсусу** — візуалізація того, як різні механізми узгодження (PoW, PBFT) впливають на швидкість підтвердження запису та стійкість мережі до атак при однаковому навантаженні.
8. **Демонстрація стійкості до атак** — керований сценарій, що імітує Sybil-атаку та спробу заднього датування, і показує реакцію системи на них.

*Опційне розширення поза базовим обсягом:* зберігання самого файлу документа в IPFS, з фіксацією у блокчейні лише його хешу.

## Ролі користувачів

1. **Установа-видавець (Issuer)** — заклад освіти чи інша уповноважена організація. Видає нові документи, підписує їх, переглядає власний журнал видачі, відкликає видані документи. Кожна установа керує власним вузлом мережі.
2. **Власник документа (Holder)** — особа, якій видано документ (студент, випускник). Переглядає список власних документів, ділиться посиланням/QR-кодом для перевірки третьою стороною. Не може змінювати чи видавати документи.
3. **Верифікатор (Verifier)** — будь-який зовнішній користувач без облікового запису (роботодавець, інша установа, служба перевірки). Перевіряє автентичність документа за хешем/QR-кодом і бачить його статус. Доступ публічний, без реєстрації.
4. *(Опційно, лише для дослідницької частини роботи)* **Дослідник мережі** — переглядає метрики консенсусу, запускає демонстраційні сценарії атак, аналізує результати порівняння алгоритмів. У продакшн-системі ця роль не потрібна.
